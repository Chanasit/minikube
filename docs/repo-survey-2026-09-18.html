Deploy model

Terraform bootstraps once; Flux owns the rest

terraform/main.tf does two things and then steps back: it creates the orbstack minikube cluster (docker driver, cni = bridge, default-storageclass + storage-provisioner addons), then runs flux_bootstrap_git against this repo. From that point cluster state comes from git. No kubectl apply, no live patching — the Kustomization sets prune: true, so anything hand-created is deleted on the next pass.

Every workload is a Flux HelmRepository + HelmRelease pair. Only random-logger (3 replicas, chentex/random-logger) is a plain Deployment.

  • CRITICAL

    Kafka SASL credentials committed in plaintext

    clusters/apps/logging/kafka.yaml:84–104

    Five sets of credentials sit in git as literal strings: the interbroker user, the controller user, and three client users (app1, logstash, metrics). The repo is public on GitHub. This also breaks the repo's own stated secrets policy.

    Fix Move all six values into a Kubernetes Secret and reference it via valuesFrom on the HelmRelease, or SOPS-encrypt them. Rotate every value — git history keeps the old ones.

    fixed0f497ee, af6f7b5: passwords now come from Secret kafka-sasl (existingSecret), generated by Terraform random_password in terraform/secrets.tf. The new values differ from the ones left in history.

  • HIGH

    Kafka alone requests more than the node has

    clusters/apps/logging/kafka.yaml — controller.replicaCount 3, resources.requests 1500m / 5Gi

    Three controllers request 4.5 CPU and 15Gi against a node sized 6 CPU / 16g — before Istio, Elasticsearch, Loki, and Prometheus ask for anything. Storage is worse: 3 × 50Gi controller PVCs plus a 100Gi persistence.size, on minikube's standard hostPath class. Heap is set to -Xmx4g inside a 5Gi request. Pods will sit Pending.

    Fix For a laptop lab: replicaCount: 1, requests ~500m / 1Gi, heapOpts -Xmx768m, PVC 8Gi. Drop replicationFactor and min.insync.replicas on the provisioned topic to match.

    fixeda6e6d49: 3 × 100m / 768Mi, heap -Xmx512m. 2050db5 dropped the dead top-level persistence.size: 100Gi (chart 32.4.3 has no such key). Controller PVCs stay 50Gi: volumeClaimTemplates are immutable and hostPath does not enforce size. Topic replicationFactor: 3 / min.insync.replicas: 2 kept; they match 3 controllers.

What holds

Already right, leave it alone

  • Secret hygiene at the Terraform layer. git ls-files terraform/ returns four files: main.tf, secrets.tf (generates app passwords, holds no secret values), .tool-versions, secret.auto.tfvars.example. State, tfvars, and .env are all present on disk and correctly ignored.
  • github_token is a sensitive variable with no default, passed via TF_VAR_github_token.
  • Every chart version is pinned — no floating tags, no latest on a Helm chart anywhere in the repo.
  • Dependency ordering is explicit where it matters: fluent-bit declares dependsOn: kafka, and install/upgrade remediation retries are set on the fragile releases.
  • The directory convention is consistent. Every app dir is namespace + manifests + kustomization, which is why the recursive reconcile works without a top-level file.
  • Promtail → Loki → Grafana is wired end to end, including the random-logger Deployment as a traffic generator to prove it.

Working the cluster

# bring the lab up
cd terraform && terraform init && terraform apply

# reconcile status / force a sync after push
flux get kustomizations -A
flux reconcile kustomization flux-system

# validate before commit
terraform fmt -check
trivy config .

Changes go through git. Push to master, wait ~1m, or force the reconcile. A kubectl apply against this cluster is drift and gets pruned.
