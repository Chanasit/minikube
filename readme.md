# Personal Minikube Setup

Local Kubernetes playground with GitOps (Flux), service mesh (Istio), logging, monitoring and stream processing — bootstrapped by Terraform, then reconciled by Flux from this repo.

## What gets deployed

`terraform/main.tf` creates a single-node minikube cluster (profile `orbstack`, docker driver, 6 CPU / 16 GB, bridge CNI) and bootstraps Flux against `clusters/apps` on `master`. Everything below is then reconciled from git:

| Namespace        | Contents                                                        |
|------------------|-----------------------------------------------------------------|
| `istio-system`   | Istio base + istiod                                             |
| `logging`        | Kafka (KRaft, SASL), Kafka UI, Fluent Bit, Loki, Promtail, random-logger |
| `monitoring`     | Prometheus, Grafana (Loki + Prometheus datasources)             |
| `elastic-system` | Elasticsearch + Kibana                                          |
| `redis-system`   | Redis (1 master + 1 replica, auth on)                           |
| `weave`          | Weave GitOps UI                                                 |

## Prerequisites

- [Terraform](https://developer.hashicorp.com/terraform/install) 1.15.2 (see `terraform/.tool-versions`)
- Docker runtime ([OrbStack](https://orbstack.dev/) or Docker Desktop)
- [kubectl](https://kubernetes.io/docs/tasks/tools/) and [flux CLI](https://fluxcd.io/flux/installation/)
- [minikube](https://minikube.sigs.k8s.io/docs/start/) CLI (optional — the Terraform provider creates the cluster; the CLI is for `minikube ssh` etc.)
- GitHub PAT with `repo` scope, for Flux bootstrap
- ≥ 16 GB RAM free for the cluster

## Quick start

```bash
export TF_VAR_github_token=...   # GitHub PAT, never commit it
cd terraform
terraform init
terraform apply
```

Alternatively copy `terraform/secret.auto.tfvars.example` to `secret.auto.tfvars` (gitignored) and fill in the token.

App credentials (Kafka SASL, Loki MinIO, Redis, Weave admin) are generated by Terraform (`terraform/secrets.tf`) and stored as Kubernetes Secrets — none live in git. On a fresh cluster, if `terraform apply` fails waiting for a Flux-owned namespace, re-run it once Flux has created it.

## Day-to-day

Cluster state comes from git. Change a manifest, push to `master`, Flux applies it (~1 min). Do not `kubectl apply` or patch live objects — Flux prunes drift.

```bash
flux get kustomizations -A                   # reconcile status
flux reconcile kustomization flux-system     # force sync after push
kubectl get pods -A                          # cluster status
```

Validate before commit:

```bash
terraform -chdir=terraform fmt -check
trivy config .
```

## Access

```bash
# Grafana (admin password generated by the chart)
kubectl get secret grafana -n monitoring -o jsonpath='{.data.admin-password}' | base64 -d
kubectl port-forward -n monitoring svc/grafana 3000:80

# Weave GitOps UI (user admin)
terraform -chdir=terraform output -raw weave_admin_password
kubectl port-forward -n weave svc/weave-gitops 9001:9001
```

## Layout

```
terraform/            cluster + Flux bootstrap + generated app Secrets
clusters/apps/
  flux-system/        Flux-generated, do not edit
  <app>/              namespace.yaml + manifests + kustomization.yaml per app
docs/                 repo survey
```
